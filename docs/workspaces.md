# 多个发布工作区

工作区是一套独立的发布资料和记录。例如「R18 创作」启用指定平台，「全年龄作品」启用所有需要的平台。程序不会根据文件内容自动分类；在当前工作区导入和发布的内容归属于该区。

## 创建与切换

1. 点击左侧工作区旁的管理按钮，或侧栏底部“工作区管理”。窄窗口使用顶部“管理”。
2. 点击“新建工作区”，填写名称，选择“未分类 / 全年龄 / R18”。名称最多 80 字，同名不可重复。
3. 勾选该区使用的插件；可以“全选插件”，也可以不选任何插件，仅保存本地归档。
4. 点击“创建并进入”。新工作区不会复制其他区的账号、草稿或历史，首次发布需要自行选择目标账号。
5. 使用左侧或窄屏顶部的工作区下拉框切换。当前草稿和账号勾选先保存，保存失败会留在原工作区并提示错误。重启后恢复上次选择。

在工作区管理中可修改名称、分类和插件范围。内容分类是工作区标识，插件上传上下文会收到该分类；具体平台字段由插件实现。程序没有自动内容识别或平台适用性判断。

## 独立保存的内容

| 数据 | 行为 |
| --- | --- |
| 插件选择 | 每区单独启用，新增插件不会自动加入已有工作区 |
| 草稿与附件登记 | 分别保存，同一个原文件显式导入两个区时有不同附件记录 |
| 账号与默认勾选 | 同一插件在各区管理自己的账号标识与选择 |
| 历史归档 | 副本和索引写入所属工作区，只能在所属区进行历史补传 |
| 上传记录、重试与去重 | 查询和修改限定在所属区，其他区的成功记录不影响此区 |
| 定时计划 | 所属区后台执行，切换界面不暂停；每区最多同时执行两个任务 |
| 插件自用数据 | 上传上下文提供该区的 `plugin-data/<插件 ID>/`；插件按此位置保存自己的配置 |

插件文件统一安装在全局 `plugins/`，不必在每个工作区复制程序。插件安装、更新与清单禁用需要重启；已安装插件在工作区内的启用选择立即生效。待接入或加载失败的插件即使勾选，也不能实际上传。

停用插件会保留账号与历史；如果它还有排队、执行中或暂停计划里的上传任务，保存会提示先完成或取消这些任务。强制本地归档始终执行，不受“本地导出”插件的勾选影响。

应用打开时，全部工作区的已提交任务都继续运行。关闭应用不会定时唤醒；重启后的待执行计划继续保持间隔，运行中被中断的任务仍需核对后手动重试。目前最多支持 32 个工作区。

## 旧数据与目录

升级后原有全部资料保留在“默认工作区”，路径不变。旧历史不会按分类自动拆分，也没有跨区移动 / 复制历史的操作。

```text
数据根目录/
  workspaces.sqlite3                 工作区 ID 索引、上次选择
  upload-hub.sqlite3                  默认工作区数据库
  archives/                          默认工作区的原有归档
  deliveries/                        默认工作区的本地导出
  plugin-data/<插件 ID>/              默认工作区的插件配置目录
  workspaces/<工作区 UUID>/
    upload-hub.sqlite3                该区独立数据库
    archives/                        该区归档
    deliveries/                      该区导出
    plugin-data/<插件 ID>/            该区插件配置目录
    workspace.lock                   该区进程锁
```

“工作区管理 → 运行与存储”显示当前区的实际路径。完整备份应关闭应用并保存整个数据根目录，包括工作区索引和所有子目录。归档索引仍含绝对路径，当前没有跨根目录搬迁功能。

这属于应用数据隔离；外部插件仍是以当前用户权限运行的本机程序。插件开发者需遵守上下文提供的存储路径，不能把所有工作区的账号状态写入同一个插件安装目录。Pixiv 已提供按工作区和账号隔离的配置向导与 Windows DPAPI 凭据；统一凭证管理面板仍未实现。

Pixiv 会把工作区分类映射为真实投稿年龄限制。有活动上传或补传任务时，工作区年龄分类不能修改，需先完成或取消任务。各账号的 Pixiv 标签、AI 标记和公开范围在执行时读取配置，修改前请先暂停相关计划。
