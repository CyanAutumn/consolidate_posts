测试中发现 Windows 下清单文件句柄未释放会导致归档目录重命名失败，已在提交归档之前显式关闭句柄，相关归档用例通过。

新增验证涵盖：

- 强制归档不受平台注册驱动替换影响；上传失败仍保留副本，删除源文件后重启并重试成功。
- 归档失败阻止上传；修复保存位置后重试，旧尝试保留并防止重复重试。
- 按账号独立去重、已成功内容显式重复、活动计划不能重复排队；补传不再次生成归档。
- 到期前不执行；暂停状态跨重启保留；恢复后继续；模拟多日离线时仍按真实派发间隔领取任务。
- 取消计划阻止待执行任务，并返回运行任务的取消信号。
- 附件同样大小、同样修改时间但内容已变化时，SHA-256 核验阻止导出；缺失副本在预览中跳过。
- 旧版归档迁移使用已有副本，源文件已删除仍能补传；同目录双实例被进程锁拒绝。
- 界面可单独归档、新建账号并带入补传页面、全选历史、转换本机时间、修改配置使预览失效，以及暂停 / 继续 / 取消计划。
- 目录插件启动真实子进程，使用统一入口完成上传和历史补传；后装插件也能补传安装前的旧历史。
- 插件禁用、重复 ID、缺失入口、越界入口路径、清单版本错误和缺失插件目录不会阻断核心归档。
- 插件校验拒绝、超时、运行中取消、崩溃、非法 stdout 和无效进度均不产生虚假成功。
- 旧数据根目录、草稿、附件 ID 与归档路径保留；新工作区拥有独立数据库及文件目录。
- 跨区附件、任务、历史 ID 被拒绝，禁用插件不能通过提交、账号创建、重试或补传绕过；空插件工作区仍能留档。
- 切换后后台计划继续完成；重启后各区草稿、分类、账号勾选、暂停计划和上次选择均保留。
- 存在活动任务时阻止停用相关插件；取消任务后可停用，历史不丢失。新装插件不会自动加入已有区。
- 实际外部插件进程收到各区身份、分类和 `plugin-data/<插件 ID>`，两个区分别写出配置记录。
- 界面切换先保存当前编辑；保存失败保持原区和输入；迟到的旧工作区刷新不能覆盖新工作区历史。

前端测试替身验证交互和协议调用，Rust 测试验证实际磁盘输出和队列状态。原生文件对话框、系统拖放事件、IPC 到页面的完整人工点击流程，仍需在可操作的桌面窗口中验收。未进行真实平台上传、长期定时或大规模历史压力测试。
